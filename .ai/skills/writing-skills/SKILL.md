# writing-skills — Skill 文档编写技能

> 用 TDD 方式编写 Skill 文档：先定义期望行为，再填充实现步骤。适用于新建技能，或重写失效/不合格的技能文档。

---

## Skill 文档必需结构

### frontmatter（文件头 `---` 包裹的 YAML 元数据）

| 字段 | 必填 | 说明 |
|------|------|------|
| `name` | ✅ | 技能标识符（kebab-case，如 `writing-skills`），注册/安装以它为准 |
| `description` | ✅ | **一行**简介，≤120 字。未来会话靠它决定是否调用本技能，须写明「何时用、解决什么」 |
| `scope` | ❌ | `project`（默认，仅当前仓库可用）或 `global`（所有项目可用） |
| `runAs` | ❌ | `inline`（默认，直接读取执行）或 `subagent`（在独立子 Agent 中执行） |
| `allowedTools` | ❌ | 仅 `runAs: subagent` 时有效：子 Agent 可用的工具白名单 |
| `model` / `effort` | ❌ | 指定执行子 Agent 的模型与推理强度（仅 `runAs: subagent` 时有意义） |

`description` 写作要点：写明**触发场景 + 产出**，如「编码前根据场景查阅对应 Agent 的代码模板」优于「编码索引」。已有技能保留原 description，不随意改动（可能影响调用方匹配）。

### 正文结构建议（按序组织，非强制）

1. **触发条件** — 什么时候该用本技能（一段话或一个列表）
2. **流程** — 步骤化的可执行步骤（编号列表，每步写「做什么 + 产出什么」）
3. **输出/示例** — 期望的调用方式、输出格式或示例代码
4. **注意事项** — 常见坑、边界情况、与其他技能的协作

### 保存位置

- `scope: project`（默认）→ 当前仓库技能权威源 `.ai/skills/<name>/SKILL.md`，写好后运行 `./sync_ai_config.sh` 同步到各工具发现路径（`.claude/skills/`、`.github/skills/`、`.agents/skills/`、`.reasonix/skills/`）
- `scope: global` → 全局 skills 目录（对所有项目生效，`name` 须全局唯一）

## TDD 流程

编写 Skill 文档按以下 4 步进行：

1. **定义输入与输出契约** — 明确 `description`（何时触发、触发条件）与正文要达成的效果（触发后应产出什么、按什么步骤执行）。这一步是整篇文档的「测试用例」。
2. **写一个调用示例** — 描述期望用法：什么场景下调用、传什么参数、期望得到什么结果。示例要具体到可直接照做。
3. **填充执行步骤** — 按调用示例倒推，写出可逐步执行的流程，每步具体到「做什么 + 产出什么」，不留模糊步骤。
4. **验证示例是否能按步骤跑通** — 拿着第 2 步的调用示例，逐条对照第 3 步的步骤走一遍；发现断点（缺步骤、有歧义、缺校验）立即补上。

---

## 校验

写完（或修改）后逐项检查：

- [ ] `name` 与 `description` 均存在且非空 — **缺失任一字段会导致注册/安装失败**
- [ ] `description` 为一行且 ≤120 字
- [ ] 使用了 `runAs: subagent` 时，`allowedTools` / `model` / `effort` 已按需配置
- [ ] 正文含触发条件、流程、示例，且步骤可逐条执行
