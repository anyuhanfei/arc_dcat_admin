## 一、五层架构（API 层）

```
Controller → Service → Repository → Model
              ↓
          Resource（输出转换）
              ↑
          Request（参数验证）
```

| 层 | 职责 | 禁止 |
|----|------|------|
| **Controller** | 收参→验证→调 Service→返回 | 业务逻辑、try-catch、直接操作 Model |
| **Service** | 业务逻辑、调 Repository/其他 Service/工具类 | 直接 `use App\Models` 做数据库读写 |
| **Repository** | 本表 CRUD + 复杂查询 | 业务逻辑、跨表事务（Service 层管） |
| **Resource** | 字段转换、隐藏内部字段、分页结构组装 | 业务逻辑 |
| **Request** | 参数验证（每个方法一个文件） | 业务逻辑 |

> **Service 层无直接操作 Model 的权限**：数据查询/写入必须经 Repository 转发。Service 可自由调用其他 Service、工具类、三方对接类。

## 四、PHP 8.4 / Laravel 13 编码约束

| 约束 | 说明 |
|------|------|
| **全量类型声明** | 所有方法参数、返回值、类属性必须声明类型；闭包参数和返回值也声明类型 |
| **禁用已弃用函数** | 不使用 `utf8_encode()` / `utf8_decode()`（PHP 8.4 弃用），用 `mb_convert_encoding()` 替代 |
| **内置数组函数** | 查找用 `array_find()` / `array_find_key()`，判断用 `array_any()` / `array_all()`（PHP 8.4 内置），不写 foreach 手动查找 |
| **readonly DTO** | 请求/响应数据传输对象、值对象用 `readonly class`，属性构造后不可变 |
| **固定枚举用 enum 类** | 状态/类型等固定枚举用 PHP enum 类（`app/Enums/`，int 或 string backed），Model `$casts` 声明 Enum::class；**禁止使用 const + STATUS_MAP 常量数组方式** |
| **属性钩子** | Model 访问器/修改器必须用 PHP 8.4 属性钩子，不写 Laravel `Attribute::make()` 或旧的 `getXxxAttribute()` / `setXxxAttribute()` |
| **批量写入用 upsert** | 批量创建/更新关联记录用 `Model::upsert($data, $uniqueBy, $update)`，禁止循环 firstOrCreate/create；唯一键由迁移联合索引保证 |
| **关联查询用 whereRelation** | 关联条件查询用 `Model::whereRelation('relation', 'field', $value)`（Laravel 10+ 内置），比 `whereHas` 更简洁；嵌套条件用闭包 |
| **耗时 IO 不阻塞** | 外部 HTTP 调用、文件处理、大计算等耗时操作必须用 Laravel Queue（Job 放 `app/Jobs/`），不同步阻塞请求 |
| **配置不硬编码** | 第三方密钥、环境相关值读 `config()`，config 读 `env()`，禁止在代码里写死密钥/URL/开关 |
| **功能开关用 Pennant** | 灰度发布、AB 测试、功能开关用 Laravel Pennant，不写 `if (env('XXX'))` 硬编码判断 |
| **健康检查用 Health** | 如需健康检查端点，用 Laravel 内置 Health 组件（`php artisan health:install`），不手写 |
| **队列任务规范** | 耗时任务（短信、邮件、文件处理、第三方回调）必须走 Queue；Job 类放 `app/Jobs/`，失败重试次数在 Job 类声明 `$tries` |

## 五、Model 规范

```php
// ✅ 正确写法
class SysArticle extends Model
{
    protected $fillable = ['title', 'content', 'status', 'category_id'];

    protected function casts(): array
    {
        return [
            'status' => PublishStatus::class,  // enum 类
            'published_at' => 'datetime',
        ];
    }

    // PHP 8.4 属性钩子（访问器/修改器）
    public function contentSummary(): string
    {
        return mb_substr(strip_tags($this->content), 0, 100);
    }
}

// ❌ 禁止
// - 不声明 $fillable（用 unguarded() 绕过）
// - const STATUS_DRAFT = 0; const STATUS_MAP = [...]
// - getTitleAttribute() / setTitleAttribute() 旧写法
// - Attribute::make() 写法
```

## 六、API 接口规范

### 统一响应格式

```php
// 成功
return success('操作成功', $data);
// → {"code":1,"msg":"操作成功","data":{...}}

// 失败（Service 层抛出，Controller 不捕获）
throwBusinessException('错误信息');
// → {"code":0,"msg":"错误信息","data":{}}
```

### 分页结构（Controller 手动组装）

```php
$result = $this->service->list($params);  // 返回 LengthAwarePaginator

return success('success', [
    'total'       => $result->total(),
    'count'       => $result->count(),
    'perPage'     => $result->perPage(),
    'currentPage' => $result->currentPage(),
    'lastPage'    => $result->lastPage(),
    'firstItem'   => $result->firstItem(),
    'lastItem'    => $result->lastItem(),
    'datas'       => ArticlesResource::collection($result->items())->toArray($request),
]);
```

### Resource 转换（success() 不接受 JsonResource，必须 toArray()）

```php
// 单条
return success('success', (new UserResource($user))->toArray($request));

// 列表
return success('success', UserResource::collection($list)->toArray($request));
```

### Swagger 注解

- 所有 API 方法必须用 `#[OA\Post]` / `#[OA\Response]` 等 OpenApi 注解标注
- 未标注 Swagger 的方法视为废弃方法，修改时不要理会

## 七、安全规范

| 规范 | 说明 |
|------|------|
| **越权校验（条件式）** | 私有资源（用户订单、个人资料）必须校验 `user_id` 归属；公开资源（文章、公告、商品列表）无需校验 |
| **参数验证** | 所有接口参数必须经 Request 类验证，禁止直接用 `$request->input()` 不验证 |
| **SQL 注入防护** | 使用 Eloquent 查询构造器，禁止原生 SQL 拼接用户输入 |
| **XSS 防护** | 输出经 Resource 转换，富文本字段存储前过滤危险标签 |
| **敏感信息隐藏** | password、remember_token、session_key 等字段在 Model `$hidden` 中声明，Resource 不输出 |
| **验证码防重放** | 验证码验证成功后立即销毁（`destroyCode`），防止重复使用 |
| **Token 管理** | 登录用 Sanctum `createToken`，退出删除当前 token，重置密码后删除所有 token |

## 九、AI 协作规则

### 子 Agent 派发（规则 3）

主会话（编排层）不做任何代码编写。所有涉及创建/修改代码文件的任务，必须派发给专门的编码 Agent/子 Agent 执行。

| 优先级 | 任务涉及目录 | 编码角色 |
|--------|-------------|---------|
| 1 | `app/Api/` / `routes/api.php` | API 开发（`agent-api.md`） |
| 2 | `app/Admin/` / `app/Admin/routes.php` | 后台管理（`agent-admin.md`） |
| 3 | `database/`、`app/Models/`、表结构变更 | 数据库（`agent-database.md`） |
| 4 | `app/Integrations/` / 三方接口对接 | 三方对接（`agent-thirdparty.md`） |
| 5 | 配置修改 / Artisan 命令 / Composer / 前端 / 其他 | 兜底（`agent-default.md`） |

### 并行边界

- **跨模块可并行**：不同模块的独立子任务可同波并行派发
- **同模块内严格串行**：按 database → api → admin 顺序分波

### 需求追问（规则 1）

边界模糊或有多个可选方案时，必须先追问确认，每次只问一个问题并附推荐答案。

可跳过追问的情况：
- 明确的单文件修改
- 不改接口参数和返回结构的调整
- 用户已给出非常具体且无歧义的指令
- 修复明确报错信息的 Bug

### 临时文件（规则 2）

所有对话中生成的项目相关文件（功能文档、SQL 更新、交接文档、验证脚本等），必须保存到项目根目录的 `tmp/` 下。

## 十、常见错误速查

| 错误现象 | 原因 | 解决方案 |
|---------|------|---------|
| `success()` 传入 Resource 报错 | success() 不接受 JsonResource | 必须 `->toArray($request)` 转换 |
| Controller try-catch 后 error() 不返回 | try-catch 捕获了 BusinessException | Controller 层禁止 try-catch，异常由全局处理器处理 |
| Service 直接 `$user->save()` 违规 | Service 层无直接操作 Model 权限 | 改为 `$this->repository->save($user)` |
| Model 用 `const STATUS_MAP` 违规 | 固定枚举必须用 enum 类 | 改为 `app/Enums/` 下的 PHP enum 类 |
| 分页接口 datas 字段缺失 | Service 返回 Paginator，Controller 需手动组装 | Controller 手动组装 total/count/perPage/.../datas 结构 |
| `unguarded()` 绕过批量赋值 | Model 必须声明 fillable | 补全 `$fillable`，移除 unguarded |
| 旧的 `getXxxAttribute()` 写法 | 必须用 PHP 8.4 属性钩子 | 改为属性钩子或普通方法 |
